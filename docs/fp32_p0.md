# FP32 P0 优化记录（2026-09-24）

基线：`main` 的 `da4a695`。实施分支：`codex/fp32-p0-optimization`。
本轮保留现有求解算术，完成缓存与梯度需求相关的四项改动。

## 已保留的改动

- **冻结输入的准备缓存**：GradMode 开启、全部输入冻结时，也允许固定叶子核复用频谱与功率准备。仍使用原 ATen 半谱求解。任一输入需要梯度时仍逐调用做可微全谱核 FFT。
- **共享频谱物化复用**：推理的 `fy` 与 `fx0` 为同一张量时，共用一次 `contiguous()` 的结果；独立 prior 不合并。当前测量未分离出这一项的独立加速。
- **缓存布局失效**：按值保存核的 sizes、strides、storage offset，避免 `.data` 布局替换在地址和版本号不变时误命中。原版本、设备、stream、InferenceMode 和 Graph 生命周期规则保留；这不意味着支持无法被版本计数发现的任意 `.data` 数值修改。
- **一阶 VJP 按需求剪枝**：s1、受限 s2 和通用分支跳过无需求的梯度分配、相关物化、逐点计算及广播归约。通用输入单梯度路径还跳过 prediction/kernel 阶段。保持共享梯度累加顺序、实部视图 stride、FP32 运算边界和高阶 ATen 回退；没有减少前向保存的激活，也没有训练谱缓存。

## 性能范围

每个进程预热 5 次，每个场景 5 轮 × 10 次，记录同步 wall time 与 CUDA event；下表是两次前后版本对照各自中位数之比的范围，定义为基线耗时 ÷ 候选耗时。小于 1 表示候选较慢。原始轮次全部保留，不以 profiler 时间代替基准。

训练算子含 padding、nearest prior、核准备、全部 FFT 和指定梯度的完整链式 VJP；不含 optimizer。训练形状 B2/C32/LR32×40，s1 为 k3/pad2（FFT36×44），s2/s3 为 k7/pad0（FFT64×80、96×120）。

完整模型加载同一预训练 checkpoint，保留默认 5 次迭代、7 个 prior block，LR8×10/s2；DataNet FFT16×20，35 次 prior FFT20×24。训练计时包括 zero_grad、forward、RGB MSE、全部 backward、Adam；每轮恢复同一 checkpoint 和相同预备更新后的优化器状态。输入与目标常驻 GPU。

**没有全场景加速。** 普通 no_grad 热推理为 0.804–1.077×，冷调用为 0.943–1.047×；例如小 s3 热调用一轮从 0.121 ms 到 0.150 ms，另一轮从 0.121 ms 到 0.122 ms。完整模型推理略慢、完整训练基本持平。保留这些结果，不把波动或未分离的物化收益包装成稳定加速。

峰值是相对调用前存活张量的额外 PyTorch allocated 内存，不是进程总显存。冷缓存仅指清空算子缓存，排除首次 CUDA 初始化、编译和数据读取。本轮没有新增 Graph miss/hit 计时或 Nsight 寄存器/DRAM 流量测量；两组独立进程是波动检查，不是统计显著性证明。

## 未通过并撤回的候选

曾尝试让 frozen + GradMode 直接进入已有 no_grad 融合求解。它改变旧冻结输出，且 5 组输入中的 4 组无法通过相对同一 FP64 参考的 Python FP32 双指标零裕量非劣检查，所以撤回了该分派，仅保留准备缓存。

必须区分两件事：旧半谱推理在这 4 组输入上也未通过更严格的全谱 Python FP32 门槛；最终方案逐字节保持旧结果。这些既有失败没有变成通过，也不能据此宣称本轮新增推理误差。被撤回候选的逐张量误差、哈希与二进制指纹一并保留。

首次新增测试还曾错误断言 s2 冷准备中不能出现任何 `roll`，随后发现其包括必要的 Hermitian 补全，已改为检查实际核 FFT 缓存命中。构建指纹也曾拒绝同一 shell 重复初始化后的工具链环境；正式基准全部在独立进程运行。

## 复现与证据

完整轮次、张量快照、成功/失败判定及 source/binary 指纹见 [fp32_p0_results.json](fp32_p0_results.json)。本地原始 JSON、测试日志和基线源码快照在 `artifacts/fp32_p0/`，其 SHA256 已写入报告。基线可由 `da4a695` 单独检出。

在配置一致的 PyTorch/CUDA/MSVC 环境运行；Windows 每条 `tools/run.ps1` 使用独立 PowerShell 进程，以免重复初始化改变严格构建指纹：

```powershell
$env:CONVERSE_PYTHON = (Resolve-Path .venv/Scripts/python.exe).Path
$env:CONVERSE_MSVC_VERSION = '14.44'
$env:TORCH_CUDA_ARCH_LIST = '12.0'
pwsh -NoProfile -File tools/run.ps1 -m unittest discover -s test -p 'test_*.py' -v
pwsh -NoProfile -File tools/run.ps1 tools/benchmark_fp32_p0.py --root '基线检出目录' --build --include-model --output artifacts/fp32_p0/repro_before.json
pwsh -NoProfile -File tools/run.ps1 tools/benchmark_fp32_p0.py --build --include-model --output artifacts/fp32_p0/repro_after.json
pwsh -NoProfile -File tools/run.ps1 tools/benchmark_fp32_p0.py --compare artifacts/fp32_p0/repro_before.json artifacts/fp32_p0/repro_after.json --output artifacts/fp32_p0/repro_comparison.json
```
