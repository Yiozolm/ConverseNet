# 数值简化分支实测

本文记录修复前的测试；后续修复与复测结果见 [缺陷修复报告](simplified_branch_fix.md)。

测试分支：`codex/numerically-stable-closed-form`，提交 `dcc9896230ec5fc7ed698beca6518b5a726bd17e`（数值代码来自 `c789554`）。对照当前 main `42f1d1cd5437751114ce671e0e055350249b62eb`，以及简化前 C++ 基线 `c7eb880`。

结论：**残差公式简化在常规模块用法下正确，精度明显优于旧公式；但该分支仍有独立 x0 与缓存缺陷，性能也未达到当前融合/rFFT 实现。** 本次只测试，没有修改该分支或切换当前 checkout。

## 方法

- 本机 RTX 5060 Ti，PyTorch 2.11.0+cu130，CUDA Toolkit 13.0，MSVC 14.44。
- 用 `git show` 把固定提交的原始源码保存到 `.build/simplified_branch/dcc98962/source/`。
- 实际编译分支的 C++ 文件，只把注册命名空间改为 `converse2d_simplified`，避免与当前算子冲突，数学代码未改。
- 直接复跑分支 `test/test_closed_form.py` 的原始测试函数：AST 仅移除 pytest 装饰器、调整导入绑定和扩展命名空间。没有使用 pytest runner；CPU/GPU 各运行一遍相同测试体。
- 额外对照不依赖 FFT 的空间域稠密线性求解，检查独立 x0 和四类梯度；补测缓存与低精度边界。
- 同一进程中对四个实现使用完全相同的输入、权重、先验和尺度测速，每项预热 5 次，再取 5 批、每批 10 次 CUDA event 均值的中位数。

复现：

```powershell
& ./.build/run.ps1 test/test_simplified_branch.py
```

通用环境中，在配置好 PyTorch/CUDA 和编译器后运行 `python test/test_simplified_branch.py`。
脚本会完成全部测量并写出 JSON；由于该分支存在下述失败项，最终退出码为非零。

## 正确性

分支原有 12 组用例在 CPU/GPU 各通过一次，共 **24/24**：

- Converse2D：scale=1/2/3/4，前向、输入/weight/bias 梯度与旧公式对照。
- USRNet 的 ConvReverseDataNet：scale=1/2/3，输入/kernel/alpha 梯度对照。
- 小 lambda 下误差改善测试。
- C++ 扩展与 Python 路径在 scale=1/2/3/4 下对照。

它们的 scale=1 都使用 x0=x，因此不能覆盖下面的独立先验问题。

### 1. scale=1 忽略独立 x0

分支 C++ 第 174 行附近：

```cpp
Tensor FX0 = scale == 1 ? FY : fft(x0);
```

这相当于在 scale=1 时无条件假设 x0=x。模块内部确实满足此条件，但公开的六参数算子允许传入独立 x0。

在 float64、独立 x0 的小规模稠密求解对照中：

| 设备 | 最大绝对差 | x0 梯度 |
|---|---:|---|
| CPU | 5.825e-2 | None |
| GPU | 2.463e-2 | None |

scale=2/3/4 的同类前向及四类梯度检查通过。当前 main 的 v7 在全部尺度上均通过。

### 2. 权重原地更新后缓存过期

缓存仍按 `psf.data_ptr()` 和尺寸等信息索引，没有版本号。测试流程为首次 no_grad 推理 → `weight.mul_(0.7).add_(0.03)` → 再推理 → 清缓存后重算。

| 设备 | 清缓存前后输出最大差 |
|---|---:|
| CPU | 1.2145 |
| GPU | 1.0989 |

这不是舍入误差，而是旧频谱被继续使用。当前 main 的对应检查通过。

### 3. inference-mode 缓存不能安全复用于输入反传

权重冻结、先在 `torch.inference_mode()` 下缓存，再令 x 需要梯度并执行前向/反传，CPU/GPU 均报错：

```text
Inference tensors cannot be saved for backward.
```

原因是分支只在 `GradMode && psf.requires_grad()` 时绕过缓存；当只有 x 需要梯度时，会复用 inference tensor。当前 main 会在 autograd 启用时绕过缓存，此检查通过。

### 4. 低精度支持有限

在输出空间尺寸 10×14 的测试中，GPU float16 报 cuFFT 尺寸非 2 的幂错误，bfloat16 报不支持；CPU 两种低精度均报不支持。这是该分支的能力限制，并非残差公式错误。当前 main 通过内部 float32 计算支持这些输入。

补充边界共 32 个检查，其中简化分支 10 个失败，当前 v7 的 16 个检查全部通过。结果文件逐项记录了前向差、梯度差和异常。

## 推理性能

B=1、kernel=3、float32、bias=0、eps=1e-5；warm-cache/no_grad。时间单位 ms。

| C×H×W / scale | 旧 main c7eb880 | 简化分支 | 当前 v2 | 当前 v7 |
|---|---:|---:|---:|---:|
| 32×128×128 / 1 | 0.3393 | 0.2035 | 0.2569 | 0.1783 |
| 32×128×128 / 2 | 1.5032 | 0.9388 | 0.9719 | 0.1961 |
| 32×128×128 / 3 | 5.4769 | 3.8494 | 3.3077 | 0.6222 |
| 64×256×256 / 2 | 20.2689 | 14.0703 | 13.8098 | 4.3228 |

简化分支比旧公式约快 1.4–1.7 倍，与当前全 FFT/ATen 基准 v2 处于相近水平。当前 v7 在这些样例中更快，大尺寸 scale=2 比简化分支快约 3.25 倍。小算子的时延容易受 Windows 调度和 GPU 时钟影响，不能据单个小样例断言稳定优势。

同次推理测试对 float64 参考的误差：

| C×H×W / scale | 旧公式 | 简化分支 | 当前 v7 |
|---|---:|---:|---:|
| 32×128×128 / 1 | 1.185e-3 | 4.935e-5 | 3.767e-5 |
| 32×128×128 / 2 | 9.294e-4 | 4.768e-6 | 4.768e-6 |
| 32×128×128 / 3 | 1.516e-3 | 3.815e-6 | 3.815e-6 |
| 64×256×256 / 2 | 1.370e-3 | 9.537e-6 | 1.001e-5 |

在有效输入契约下，两种残差实现精度相当；融合/rFFT 并不保证每个样例的绝对误差都更小。

## 训练性能

包括一次前向与梯度计算。scale=1 用 x0=x，并对 x/weight/bias 求导；scale>1 用独立 x0，并对四个输入求导。这样计时不会利用“漏算 x0 梯度”形成虚假优势。此设置与上一份报告中 scale=1 独立 x0 的训练计时不同，不能直接混合比较。

| C×H×W / scale | 旧 main ms | 简化分支 ms | 当前 v2 ms | 当前 v7 ms |
|---|---:|---:|---:|---:|
| 32×128×128 / 1 | 1.6882 | 1.1696 | 1.2673 | 1.3194 |
| 32×128×128 / 2 | 6.4537 | 4.3915 | 4.2940 | 2.6809 |
| 32×128×128 / 3 | 19.7971 | 13.3916 | 13.6099 | 8.2905 |
| 64×256×256 / 2 | 79.7044 | 59.1192 | 58.1042 | 44.8526 |

简化分支在这批训练样例中比旧公式快约 1.3–1.5 倍。小尺寸 scale=1 的一次测量优于 v7，而 scale>1 下当前 v7 更快。

## 判断

残差公式简化值得保留，当前 main 已包含这一数学方向。该分支新增的 ConvReverseDataNet 简化也通过了 CPU/GPU 测试；本次没有把它合并到 main。

不建议直接用该分支替换当前修正版：它仍缺少独立 x0、缓存生命周期和低精度支持等修复，也没有融合/rFFT 的主要速度优势。本次没有重新运行 Nsight，也未改动生产源码。
